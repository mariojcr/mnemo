# Security

Use the latest stable release when reporting a vulnerability. Include the affected version,
reproduction steps, impact and a minimal example with fictional data. Do not include live keys
or private conversation content.

If the repository's [Security page](https://github.com/mariojcr/mnemo/security) offers **Report a
vulnerability**, use that private channel. If it is unavailable, open an issue containing only a
request for a private reporting channel, without vulnerability details, and wait for a maintainer
to provide one. Do not publish exploit details in a public issue.

For deployment access controls and data handling, see [authentication](docs/auth.md) and
[data flow and deletion](docs/privacy.md).
